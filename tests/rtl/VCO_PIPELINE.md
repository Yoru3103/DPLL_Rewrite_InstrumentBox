# VCO multiplier pipeline regression

Run `powershell -ExecutionPolicy Bypass -File tests/rtl/run_vco_pipeline.ps1` with Vivado 2018.3 installed. The script uses the generated production `mult_gen_pll` and `div_gen_pll` simulation wrappers and Xilinx's installed models. Generate the multiplier simulation target with `CONFIG.PipeStages=2` first. It creates a one-stage reference multiplier wrapper by changing only its entity name and `C_LATENCY`; no behavioral replacement multiplier or divider is used.

`pll_vco_mul_div_reference.v` preserves the original production wrapper, with only the wrapper and multiplier module names changed and trailing whitespace removed. Its nonblocking divider configuration, signed 64/16 division, legacy 80-bit-to-64-bit output connection, quotient slicing and initialization behavior remain the comparison baseline.

The production change raises `mult_gen_pll` from one to two pipeline stages, delays divider input valid by one clock and delays the divisor by one clock. The multiplier inputs are sampled on the original clock. If E0 is the fast-clock edge that detects a slow-clock event, data reaches the input register at E1 and is sampled by the multiplier at E2. The old divider accepts at E3 with the live divisor at E3. The new divider accepts at E4 with the delayed divisor from E3. Adding only the valid delay would instead use the divisor from E4 and could change a result during a configuration update.

The test runs 40,000 fast clocks plus 400 drain clocks at 125 MHz, with slow clocks at 3.125 MHz with both separated and coincident rising edges. All 1,000 accepted samples in each fixture must complete after the drain. It covers the 48-bit zero, full-scale and sign-bit boundaries, multiplier/divisor boundaries including signed-divisor high-bit values, and updates both factors on every fast clock in the random phase. It compares divider-accepted valid/data/divisor tuples, actual divider output valid, and the complete output stream against the original stream delayed exactly one clock. A separate actual-IP pair compares more than 40,000 products against unsigned multiplication and checks the one-clock stage difference. Undefined startup values are excluded only until the reference first has a defined output. Zero divisors are excluded from this arithmetic comparison; their preexisting undefined behavior is unchanged by the patch.

The contract is one additional 125 MHz clock (8 ns) of control-path latency, with no change to sample cadence or arithmetic/factor association. `VCO_Input0` feeds the 125 MHz DDS directly, so frequency updates reach that DDS 8 ns later. This does not claim identical DAC waveform phase or a whole-loop transfer function with zero additional delay. Timing acceptance still requires the complete routed design to pass the project's setup/hold gates.

Outputs remain in ignored `autotune_complete.sim/vco_pipeline/`.
